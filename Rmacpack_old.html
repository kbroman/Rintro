Building R packages in MacOS X

Disclaimer: The instructions below describe what I've been doing to compile an R package for Mac OS X. Check out the file src/macintosh/INSTALL in the R source distribution for the official (and recommended) approach.

Note

There are two versions of R for the Mac: a Carbon version and a Darwin version. The Carbon version is distributed as a binary, and looks just like any other Mac software. The Darwin version, on the other hand, is unix-like, and requires the installation of X-windows.

As most Mac users are probably not interested in a unix-based version of R, I've been focussing only on the Carbon version of R for the Mac.

On the R web page, the Carbon version is listed as "MacOS (System 8.6 to 9.1 and MacOS X)" while the Darwin version is listed as "MacOS X (Darwin/X11)"

Preparations

  1. A key problem on the Mac concerns line endings. One usually has "Stuffit Expander" available on the Mac. I recommend also getting the following two programs:

    1. Suntar 2.2.3 (This runs in "Classic" (i.e. MacOS 9) mode.) It de-tars a bundle of files, fixing up the line endings in each.

    2. BBEdit Lite 6.1 for OS X. This is an text-file editor which can fix up line endings for you.

  2. Acquire the Macintosh Programmer's Workshop (MPW) software. This also runs in "Classic" (i.e. MacOS 9) mode.

  3. Download the compiled, Carbon version of R. Unstuff it and place it in Applications/rm150.

  4. Download the R source code (e.g., R-1.5.0-tar.gz). Extract it using a combination of "Stuffit Expander" and "Suntar". (Stuffit Expander will automatically gunzip it, creating the tar file, and then will start de-taring things. Cancel the latter part, thus using Stuffit Expander only for the gunzipping part. Then use Suntar to de-tar the tar file; this will fix up the line endings problem.)
    I place the resulting directory in Users:kbroman:R-1.5.0 (or the equivalent).

  5. Create empty files src/include/Rversion.h and src/include/Rconfig.h within Users:kbroman:R-1.5.0. (I open a unix window, change to the src/include directory, and use the unix tool touch.)

  6. Rename src/include/Rmath.h.in as src/include/Rmath.h.

  7. Use BBEdit to fix the line endings in Rversion.h, Rconfig.h and Rmath.h.

Building an R package for the Mac

Note: I use the example of the "qtl" package. Replace "qtl" and "kbroman" and such things with what is appropropriate for your package and your system.

  1. Build your package in Windows and place it in Applications:rm150:library. Remove the file qtl.dll from the Applications:rm150:library:qtl:libs directory.

  2. Extract the gzipped, tarred, unix source file for your package, using a combination of Stuffit Expander and Suntar (to fix up the line endings) and place the resulting directory in the equivalent of Users:kbroman:Rqtl:qtl.

  3. Create a makefile (like this one: Makefile.mac), edit it appropriately, and place it in the equivalent of Users:kbroman:Rqtl:qtl:src.

  4. Start MPW

    1. Set the directory (use Directory -> Set directory...) to the equivalent of Users:kbroman:Rqtl:qtl:src.

    2. Execute the following commands. Note that you need to use the "enter" key rather than the "return" key! 
      make -f Makefile.mac > build
build

  5. Move the file qtlLib into the directory Applications:rm150:library:qtl:libs.

  6. Use DropStuff to create a stuffit file of the Applications:rm150:library:qtl directory.
