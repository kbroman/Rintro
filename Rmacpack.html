Building R packages in MacOS X

See the official instructions in the file src/macintosh/INSTALL in the R source distribution.

Note

There are two versions of R for the Mac: a Carbon version and a Darwin version. The Carbon version is distributed as a binary, and looks just like any other Mac software. The Darwin version, on the other hand, is unix-like, and requires the installation of X-windows.

As most Mac users are probably not interested in a unix-based version of R, I've been focussing only on the Carbon version of R for the Mac.

On the R web page, the Carbon version is listed as "MacOS (System 8.6 to 9.1 and MacOS X)" while the Darwin version is listed as "MacOS X (Darwin/X11)"

Preparations

  1. A key problem on the Mac concerns line endings. One usually has "Stuffit Expander" available on the Mac. I recommend also getting the following two programs:

    1. Suntar 2.2.3 (This runs in "Classic" (i.e. MacOS 9) mode.) It de-tars a bundle of files, fixing up the line endings in each.

    2. BBEdit Lite 6.1 for OS X. This is an text-file editor which can fix up line endings for you.

  2. Acquire and install the Macintosh Programmer's Workshop (MPW) software. This also runs in "Classic" (i.e. MacOS 9) mode.

  3. Increase the amount of memory allotted to MPW. Find MPW in "finder"; control-click on MPW and select "show info". Select "Memory" and increase the preferred size and minimum size to 20480 kb.

  4. Acquire and install MacPerl. This, too, runs in "Classic" mode.

  5. Within MPW, set the directory (use Directory -> Set directory...) to the location of the MPW subdirectory within the Macperl directory. Type Install.MPW_Perl (note that you need to use the "enter" key rather than the "return" key) and follow the instructions.

  6. Download the compiled, Carbon version of R. Unstuff it and place it in Applications:rm162.

  7. Download the R source code (e.g., R-1.6.2-tar.gz). Extract it using a combination of "Stuffit Expander" and "Suntar". (Stuffit Expander will automatically gunzip it, creating the tar file, and then will start de-taring things. Cancel the latter part, thus using Stuffit Expander only for the gunzipping part. Then use Suntar to de-tar the tar file; this will fix up the line endings problem.)
    I place the resulting directory in Users:kbroman:R-1.6.2 (or the equivalent). You don't really need the whole source distribution.

  8. Copy the share directory from the R source code into the src:macintosh subdirectory in the binary distribution (e.g., in Applications:rm162).

Building an R package for the Mac

Note: I use the example of the "qtl" package. Replace "qtl" and such with what is appropropriate for your package and your system.

  1. Extract the gzipped, tarred, unix source file for your package, using a combination of Stuffit Expander and Suntar (to fix up the line endings) and place the resulting directory (say qtl) in the src:library subdirectory of the R binary distribution (e.g., in Applications:rm162).

  2. Create a makefile for your package, like the ones in src:macintosh:makefiles in the R binary distribution, and place it in that directory. Call your file qtl.mac, replacing "qtl" with the name of your package.

  3. Edit the file MakeAdd.mac within src:macintosh in the R binary distribution. You'll need to change the definitions of PACKAGES, LIBF, etc.

  4. Within MPW, set the directory (use Directory -> Set directory...) to the directory that contains the MakeAdd.mac file, and execute the following commands: 
    make MakeAdd.mac > build
build

  5. Use DropStuff to create a stuffit file of the Applications:rm162:library:qtl directory.
